## 二、分层职责

### 1. Controller 层（`app.controller`）
- **职责**：HTTP 入口、参数校验、用户身份获取、统一响应封装
- **特点**：
  - AI 流式用 SSE（`Flux<ServerSentEvent<String>>`）
  - 限流用 `@RateLimit` 注解 + AOP
  - 权限用 `@AuthCheck` 注解 + AOP
  - 精选应用列表 `@Cacheable` Redis 缓存
- **不做什么**：不直接调 LLM、不直接访问 DB

### 2. Service 层（`app.service.impl`）
- **职责**：业务编排
- **`AppServiceImpl` 是编排中心**：
  - 调 `RoutingService` 决定生成类型
  - 调 `AiCodeGeneratorFacade` 生成代码
  - 调 `VueProjectBuilder` 构建 Vue 项目
  - 调 `ScreenshotService` 异步截图
  - 写 `generation_metric` 表（监控）
- **设计**：继承 MyBatis-Flex 的 `ServiceImpl<AppMapper, App>`，自动获得 CRUD

### 3. Router 层（`router`）
- **职责**：决定 prompt 走哪种生成策略
- **两层架构**（ADR-0003）：
  - Layer 1 `RuleRouter`：关键词 + 正则，毫秒级
  - Layer 2 `AiCodeGenTypeRoutingService`：LangChain4j 结构化输出，LLM 兜底
  - 最终兜底：LLM 异常 → HTML（最便宜）
- **返回 `RoutingDecision`**：带 layer/reason/confidence/durationMs 元数据，供日志/入表/评测

### 4. Agent 层（`agent`）
- **职责**：AI 代码生成 + Tool 安全
- **`AiCodeGeneratorFacade` 门面模式**：统一入口，按类型分派
- **`codegen/parser` + `codegen/saver` 策略模式**：HTML / MultiFile 各一套解析+保存
- **`tools/safety` 三层防御**（ADR-0004）：
  - Layer 1 `PathValidator`：相对路径校验（拒绝 `..`、绝对路径）
  - Layer 2 `Sandbox`：工作目录绑定 + canonical 校验（防软链接逃逸）
  - Layer 3 `ToolCallCounter`：调用次数熔断（防死循环）

### 5. Eval 层（`eval`）—— 旁路子系统
- **职责**：质量回归评测，**不在 web 请求链路里**
- **三维评分**：RubricScorer / RenderScorer / LlmJudgeScorer
- **多轮均分**（ADR-0013）：temperature=0 + 3 轮 + 断点续跑
- **入口**：`EvalRunner.main()` 命令行运行

### 6. Metric 层（`metric`）
- **职责**：路由/生成耗时落表
- **`MonitorContextHolder`**：ThreadLocal 上下文（userId/appId）
- **`GenerationMetricService.recordRouting`**：路由完成后落表

### 7. Infra 层（`infra`）
- **横切关注点**：
  - `config/Prompt2AppProperties`：~50 配置项的强类型绑定
  - `ratelimiter`：Redis 限流（滑动窗口）
  - `aop`：`@RateLimit` / `@AuthCheck` 切面
  - `exception`：统一异常体系
  - `common`：`BaseResponse` / `ResultUtils`

## 四、技术选型原因（为什么选这些）

### 为什么用 LangChain4j 而不是直接调 OpenAI SDK？
- **抽象层**：Tool Calling / Chat Memory / 结构化输出 / TokenStream 流式 都封装好了
- **多模型支持**：OpenAI / DashScope 切换只改配置不改代码
- **代价**：1.1→1.5 升级 breaking change 多（ADR-0002 记录删了 1450 行 patch）

### 为什么用 MyBatis-Flex 而不是 JPA？
- **查询灵活**：`QueryWrapper` 链式 API，比 JPA 的 `Specification` 直观
- **代码生成**：`mybatis-flex-codegen` 自动生成 entity/mapper
- **轻量**：比 MyBatis-Plus 更现代、更少魔法

### 为什么用 Redis + Redisson？
- **Session**：Spring Session Data Redis 共享会话
- **限流**：Redisson 分布式限流（`@RateLimit` 滑动窗口）
- **缓存**：`@Cacheable` 后端
- **代价**：ADR-0011 删过一次 `RedisChatMemoryStore`（未生效的依赖要及时回收）

### 为什么用两层 Router（规则 + LLM）而不是全用 LLM？
- **成本**：规则层毫秒级 + 零 token，LLM 慢 + 贵
- **可观测**：规则层易调试，LLM 黑盒
- **兜底**：规则未命中走 LLM，保证覆盖率

### 为什么用三层 Sandbox 而不是简单的 `..` 校验？
- **软链接逃逸**：`..` 校验挡不住软链接，需要 `toRealPath` canonical 校验
- **关键文件保护**：`package.json` / `vite.config` 不能被 LLM 删
- **死循环防御**：LLM 可能死循环调 Tool，需要熔断

### 为什么有 LangGraph4j 但不用作主路径？（ADR-0007）
- **复杂度**：工作流编排对当前需求过度
- **可观测性差**：调试链路长
- **保留**：作为演示入口（`WorkflowSseController`）和未来可能路径

### 为什么有 MinIO 配置但不用？（ADR-0006）
- 当前用本地文件 + 腾讯云 COS（截图），对象存储不是当前痛点
- 留待 Phase 7+ 多用户场景再考虑

## 五、关键设计原则（贯穿全项目）

1. **配置外部化**（ADR-0010）：所有路径/Host/端口/密钥/阈值都在 `.env` + `Prompt2AppProperties`
2. **AI 工程化**：LLM 不是黑盒，通过 Router 分派 / Sandbox 防御 / Eval 评测纳入工程治理
3. **决策留档**：13 篇 ADR，每个关键选型有备选对比 + 代价分析 + 复盘指标
4. **评测先行**（ADR-0008）：重构前先建评测集，保证有回归基准
5. **模块化单体**（ADR-0001）：从微服务回退到单体，3 个服务规模不需要 RPC

## 六、给你的认知锚点

1. **`app.service.impl.AppServiceImpl` 是业务编排中心**，所有核心链路都经过它
2. **`agent.codegen.AiCodeGeneratorFacade` 是 AI 生成门面**，Controller→Service→Facade→LLM
3. **`router.RoutingService` 是入口分类器**，只在创建应用时调用
4. **`eval` 是旁路系统**，不在 web 链路，命令行运行
5. **`infra.config.Prompt2AppProperties` 是配置中枢**，所有外部化配置的入口
