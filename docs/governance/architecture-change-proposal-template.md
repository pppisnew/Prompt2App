# Architecture Change Proposal (ACP) Template

> 当 AI 或人类协作者发现需要做"架构性变更"时，**先用本模板写一份 ACP**，提交给项目所有者确认后再执行。
> ACP 不替代 ADR——ACP 是"提议"，ADR 是"决议"。一份 ACP 通过后通常会落地为一条 ADR。

---

## 何时需要 ACP

下列任一情形即触发：

- 用户指令需要触碰 `PROJECT_CHARTER.md` §3「明确不做」中的某条
- 跨 Phase 执行的请求
- 已有 ADR 需要被废弃或修订
- 新增任何技术栈（依赖 / 中间件 / LLM / 工具）
- 修改模块边界（拆分 / 合并 / 删除模块）
- 修改 Agent 流程或 Router 策略
- 新增数据库表或修改既有表结构
- 任何会让 [`docs/roadmap/milestones.md`](../roadmap/milestones.md) 的工作量估算 ±20% 的变更

## 何时不需要 ACP

- 修 bug、补测试、加注释
- 调整 prompt 文本（但不改变 prompt 接口或输出契约）
- 重构内部实现但不改变模块对外接口
- 文档自身的勘误

## ACP 模板（直接复制使用）

```markdown
# ACP-YYYYMMDD-<slug>：<提议标题>

- **提案人**：@xxx（AI 助手 / 人类）
- **提案日期**：YYYY-MM-DD
- **状态**：Pending | Approved | Rejected | Deferred
- **触发原因**：（用户哪一句话 / 哪个 PR / 哪次任务执行中发现的？）

## 1. 背景

发生了什么事让我们必须考虑这个变更？必须客观陈述事实，不夹带倾向。

## 2. 变更内容

要新增 / 修改 / 删除什么？精确到文件 / 模块 / 数据结构 / 流程节点。

## 3. 备选方案

至少列出 2 个方案，**包括"什么都不做"**。

### 方案 A：<名称>
- 实施步骤摘要
- 优点
- 缺点
- 工作量估计（人时）

### 方案 B：<名称>
…

### 方案 C：什么都不做
- 不做的代价是什么？
- 这个代价能承受多久？

## 4. 受影响范围

- **代码**：哪些 module / 类 / 文件
- **文档**：哪些 ADR / 设计文档需要新增或修订
- **Roadmap**：是否影响当前 Phase 或后续里程碑
- **评测**：是否需要新增 case 或重新跑基线
- **简历叙事**：是否削弱或加强项目卖点

## 5. 风险与回滚

- **主要风险**：3-5 条
- **回滚方案**：如果做完发现错了，怎么撤回（commit revert / 数据迁移回滚 / etc.）
- **回滚成本**：可逆性如何

## 6. 推荐与理由

提案人推荐哪个方案？为什么？

## 7. 待确认问题

- [ ] 用户是否接受 §6 推荐方案？
- [ ] 用户是否接受 §4 列出的影响范围？
- [ ] 是否需要先补一个 ADR 再执行？

## 8. 决议（用户填写）

- **决策**：_________
- **决策理由**：_________
- **后续 ADR 编号**：ADR-XXXX（如需）
- **决策日期**：YYYY-MM-DD
```

## 流程图

```
发现需要架构变更
        ↓
   填 ACP 模板
        ↓
   贴给项目所有者
        ↓
  ┌────────┴────────┐
  ↓                 ↓
Approved         Rejected/Deferred
  ↓                 ↓
写 ADR           记入 backlog.md
  ↓
执行变更
  ↓
更新 Task Record + Roadmap
```
